# Правила работы с проектом

Контекст проекта — структура, токены, ссылки на Figma, открытые задачи — в `HANDOFF.md`. Читай его первым делом. Здесь только правила работы.

## Деплой

Прод собирается из GitHub автоматически: пуш в `main` → сборка на Vercel → публикация на `danyatroyanov.com`.

- `vercel link` и ручная заливка папки `dist/` больше не используются. Проект Vercel с именем `dist` (скоуп `danyadex-3460`) привязан к репозиторию.
- Историю `main` не переписывать, force push не делать: с этой ветки деплоится прод.
- Ветки, кроме `main`, дают превью-деплой на своей ссылке и прод не трогают.
- Если сборка упадёт, прод останется на последней удачной версии. Чинится обычным коммитом.

## Проверять надо сборку, а не дев-сервер

Дев-сервер отдаёт файлы из дерева проекта как есть, в прод едет только собранный `dist`. Разница между этими множествами уже дважды молча ломала прод — на `localhost` всё выглядело правильно. Разбор реальных случаев — в `HANDOFF.md`.

```
npm test
npm run build
cd dist && python3 -m http.server 4177
```

Затем пройти три страницы — `index.html`, `artifact.html`, `ai-producer.html` — на 1440 и 375, глядя на битые запросы и консоль. `npm test` проверяет, что в сборку попали все страницы и медиа, которые запрашиваются в рантайме.

Дев-сервер, если нужен: `npm run dev` (127.0.0.1:4174).

## Коммиты

Одна строка, английский, императив. Примеры стиля — в `git log`. `dist/` и `node_modules/` лежат в `.gitignore`, коммитить их не надо.

## Параллельная работа

Над проектом работают несколько агентов. Перед правкой файла смотри `git status` и не затирай чужие изменения — так уже дважды теряли работу.
