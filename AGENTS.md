# Правила работы с проектом

Контекст проекта — структура, токены, ссылки на Figma, открытые задачи — в `HANDOFF.md`. Читай его первым делом. Здесь только правила работы.

## Деплой

Сайт `danyatroyanov.com` живёт на хостинге **Beget** (NS `beget.com`). С Vercel ушли: без VPN он не открывался в РФ.

- Пуш в `main` запускает GitHub Action `.github/workflows/deploy-beget.yml`: тесты → сборка → заливка `dist/` по FTP в папку сайта.
- Action работает, только когда в репозитории настроены секреты `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD` и переменная `FTP_SERVER_DIR`. Пока их нет, job пропускается — и **пуш сайт не обновляет**, заливать `dist/` в `public_html` приходится вручную.
- **Рабочий способ сейчас — скрипт** `scripts/deploy_beget.py`: собирает сайт, через API Beget заводит временный FTP-аккаунт, заливает `dist/` и удаляет аккаунт. Запускает владелец: `BEGET_LOGIN=<логин> BEGET_API_PASSWORD=… python3 scripts/deploy_beget.py`. Пароль API агентам не передаётся.
- Проверить, что выкатилось: хеши файлов в `dist/index.html` должны совпасть с тем, что отдаёт `https://danyatroyanov.com/`.
- Историю `main` не переписывать, force push не делать.
- Временные FTP-аккаунты, созданные для ручной заливки, удалять в панели Beget сразу после неё.
- Vercel-проект `dist` ещё привязан к репозиторию и собирает пуши вхолостую: домен на него не смотрит.

## Проверять надо сборку, а не дев-сервер

Дев-сервер отдаёт файлы из дерева проекта как есть, в прод едет только собранный `dist`. Разница между этими множествами уже дважды молча ломала прод — на `localhost` всё выглядело правильно. Разбор реальных случаев — в `HANDOFF.md`.

```
npm test
npm run build
cd dist && python3 -m http.server 4177
```

Затем пройти три страницы — `index.html`, `artifact.html`, `ai-producer.html` — на 1440 и 375, глядя на битые запросы и консоль. `npm test` проверяет, что в сборку попали все страницы и медиа, которые запрашиваются в рантайме.

Дев-сервер, если нужен: `npm run dev` (127.0.0.1:4174).
