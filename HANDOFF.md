## Что уже сделано и трогать осторожно

- **Нижняя навигация** сведена в один `bottom-nav.css` с контрактом переменных `--nav-*`. Каждая сторона маппит на них свои токены. Правка панели теперь в одном месте.
- **Прогрессивное размытие** нижней кромки: 4 слоя с геометрическим ростом радиуса и полосовыми масками. Не «один слой с маской» — иначе видны ступени.
- **ARTIFACT переведён с координат на поток.** Раньше секции имели прибитые высоты и абсолютное позиционирование, правка текста ломала раскладку. Осталось 35 абсолютных элементов — это композиция (слои мокапов, наложенные стрелки), их трогать не надо.
- **Стрелки** сведены к 2px. Важно: толщина в SVG запечена в контур, и у файлов стоит `preserveAspectRatio="none"` — растяжение по ширине меняет толщину. Размеры в CSS должны совпадать с пропорциями файла.
- **Появление блоков при прокрутке** — `assets/reveal.js`: класс `.rv` навешивается по списку селекторов, `.in` добавляется через IntersectionObserver. Механика скопирована с lazimjarif.com.
- **Изображения**: шоты пережаты с 13.9 MB до 0.24 MB (WebP под ретину). Такой же перебор возможен в мокапах кейсов — не проверялось.

## Деплой

**Сайт на Beget, не на Vercel.** `danyatroyanov.com` смотрит на Beget
(NS `ns1/ns2.beget.com`, IP `45.130.41.82`). С Vercel переехали 13 сентября:
без VPN он не открывался в РФ.

**Автовыкатка** — GitHub Action `.github/workflows/deploy-beget.yml`. На пуш в
`main`: `npm ci` → `npm test` → `npm run build` → заливка `dist/` по FTPS.
Экшен хранит на хостинге файл состояния и заливает только изменившееся.

Чтобы он заработал, один раз настроить (делает владелец, не агент):

1. В панели Beget завести постоянный FTP-аккаунт с доступом к папке сайта.
2. На GitHub: Settings → Secrets and variables → Actions.
   - Secrets: `FTP_SERVER` (FTP-хост из панели Beget), `FTP_USERNAME`, `FTP_PASSWORD`.
   - Variables: `FTP_SERVER_DIR` — путь к папке сайта от корня FTP-аккаунта,
     с `/` в конце (обычно `danyatroyanov.com/public_html/`; сверить в панели).
3. Actions → Deploy to Beget → Run workflow, дождаться зелёного.

Пока переменной `FTP_SERVER_DIR` нет, job пропускается: **пуш код сохраняет,
но сайт не обновляет.** Тогда `dist/` заливается в `public_html` руками.

- Проверка выкатки: хеши в `dist/index.html` совпадают с живым
  `https://danyatroyanov.com/`.
- Временные FTP-аккаунты для ручной заливки — удалять сразу после неё.
- Если Beget откажет в TLS, в workflow поменять `protocol: ftps` на `ftp`.
- Vercel-проект `dist` ещё привязан к репозиторию и собирает вхолостую —
  можно отвязать в панели Vercel, на сайт это не влияет.

### Проверять надо сборку, а не дев-сервер

Дев-сервер отдаёт файлы из дерева проекта как есть. В прод едет только то, что
Vite положил в `dist`. Между этими множествами есть разница, и она уже дважды
ломала прод молча — на `localhost` всё выглядело правильно.

Как проверить перед пушем:

```
npm run build
cd dist && python3 -m http.server 4177
```

и пройти все три страницы на 1440 и 375, глядя на битые запросы и консоль.

**Что ловится только так (реальные случаи):**

- `<script src="assets/reveal.js?v=1">` без `type="module"` Vite в сборку не
  берёт — файл в `dist` не попадал никогда, на проде отдавал 404, появления
  при прокрутке не работали ни дня. Все скрипты подключать модулем.
- Абсолютные пути строкой (`"/assets/…"` внутри JS) не проходят через сборщик:
  в дев-сервере резолвятся от корня проекта, в проде ведут в никуда. Ассеты
  подключать `import`-ом, чтобы Vite их захешировал и положил в `dist`.
- Регистр путей. macOS его игнорирует, Linux у Vercel — нет. Опечатка в
  регистре живёт локально и падает только на проде.

## Правила совместной работы

- **Версии в ссылках на CSS обязательны.** Браузер держит файлы в кеше, и правка «не приезжает». Меняешь css — меняй `?v=` в подключении. Это уже несколько раз съедало время.
- SVG и картинки тоже кешируются: при замене файла добавляй версию в `src`.
- Оговорка к двум пунктам выше: `?v=` — приём для дев-сервера. В сборке Vite
  сам хеширует имена файлов, там версии не нужны. И на `<script src>` строка
  `?v=` мешает сборщику забрать файл — см. раздел про деплой.
- Перед правкой файла проверь, не изменил ли его второй агент — работаем параллельно и уже дважды затирали друг друга.
